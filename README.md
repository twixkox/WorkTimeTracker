# ⏱️ WorkTimeTracker — учёт рабочего времени и трудозатрат

Веб-приложение для производственных подразделений на **ASP.NET Core Razor Pages**. В нём есть:
- дневные и недельные табели;
- учёт работ по катерам, участкам и видам работ;
- согласование табелей и история изменений;
- отчёты, дашборды и экспорт в Excel;
- уведомления, роли и административная панель.

## Возможности

### Для сотрудников
- **Дневной табель.** Начало и окончание смены, затраченное время, номер катера и описание выполненных работ.
- **Недельный режим.** Для отдельных участков доступен табель сразу за всю неделю.
- **Упрощённый режим.** Склад и водители указывают только время смены, без строк трудозатрат и согласования.
- **Черновики.** Табель можно сохранить, вернуться к нему позже и отправить на проверку после завершения.
- **История.** Просмотр прошлых табелей, статусов и комментариев мастера.
- **Подсказки.** Автоматический расчёт продолжительности смены, вычет обеда и предупреждения о переработке.

### Для мастеров участков
- Табели сотрудников своего участка и собственный табель в разделе «Мой табель».
- Проверка суммы часов, переработок и незаполненных сведений.
- Утверждение и отклонение табелей с комментарием.
- Редактирование с записью действий в журнал аудита.
- Сводка по катерам и загрузке участка.
- Экспорт данных участка в Excel и печатная форма табеля.

### Для начальника производства
- Все подразделения, сотрудники и табели в едином интерфейсе.
- Сводные отчёты по трудозатратам, катерам и участкам.
- Дашборды с распределением и динамикой рабочего времени.
- Одноэтапное утверждение и отклонение табелей работников.
- Экспорт производственных отчётов в Excel.

### Для администратора
- Управление пользователями, ролями и привязкой сотрудников к учётным записям.
- Справочники подразделений, сотрудников, катеров и видов работ.
- Управление составом подразделений и параметрами расчёта рабочего времени.
- Импорт сотрудников из Excel.
- Журнал аудита действий и системный журнал с разделением по уровням.
- Доступ ко всем отчётам и производственным разделам.

### Уведомления
- Внутрисистемные уведомления о событиях и изменениях табелей.
- Контроль сотрудников без табеля за рабочий день.
- Сводное уведомление мастера участка после окончания смены.

## Роли

| Роль | Основные возможности |
|---|---|
| **Employee** | Заполнение своего табеля, черновики, отправка на согласование, история |
| **SectionMaster** | Собственное время без согласования; табели только своего участка, проверка, согласование, сводки и экспорт |
| **ProductionHead** | Все участки, производственная аналитика, отчёты и одноэтапное согласование; создание инженерных задач; собственный табель не заполняет |
| **ChiefEngineer** | Создание и редактирование инженерных задач, назначение активного инженера, комментарии и вложения |
| **Engineer** | Работа с назначенными активными задачами: плановый срок, начало и завершение работы, комментарии и вложения |
| **Admin** | Полный доступ, кроме заполнения собственного табеля: пользователи, справочники, настройки, аудит, журналы, согласование и отчёты; создание и редактирование инженерных задач |

Одна учётная запись имеет одну роль и не более одной привязанной карточки сотрудника с одним подразделением.

## Инженерные задачи и Telegram

Инженерные задачи создаются на сайте и в настроенном инженерном Telegram-чате. Создавать их могут
**ProductionHead**, **ChiefEngineer** и **Admin**. **ChiefEngineer** и **Admin** редактируют задачи
и назначают активного сотрудника с ролью **Engineer**.

Текущий назначенный инженер может указать плановый срок, взять задачу в работу и отметить её выполненной:
`Назначена → В работе → Выполнена`. Возврат выполненных задач из Telegram не поддерживается.
Пользователи с доступом к инженерному разделу могут просматривать задачи, добавлять комментарии
и вложения. Максимальный размер одного файла — **20 MiB**.

Внутренние уведомления и уведомления в Telegram отправляются параллельно. Если Telegram недоступен
или бот отключён, внутреннее уведомление и изменение задачи сохраняются.

### Привязка Telegram

1. Войдите на сайт и откройте **Профиль**.
2. В блоке Telegram нажмите генерацию одноразового кода. Код действует **10 минут**;
   создание нового кода отзывает предыдущие.
3. Откройте бота в Telegram и отправьте `/start КОД`, подставив код без пробелов внутри него.
4. Проверьте статус привязки в профиле. Там же можно отвязать Telegram-аккаунт.

Код нельзя использовать повторно. Один Telegram-аккаунт можно привязать только к одной учётной записи.
Все действия бота выполняются от имени привязанного пользователя и повторно проверяются по его текущим ролям;
бот не отправляет сообщения от личного аккаунта сотрудника.

### Команды и кнопки

| Команда | Назначение |
|---|---|
| `/start` | Показать справку и состояние привязки |
| `/start КОД` | Привязать Telegram по коду из профиля |
| `/newtask` | Пошагово создать задачу в инженерном чате |
| `/tasks` | Показать мои активные задачи |
| `/completed` | Показать выполненные задачи |

При создании в чате бот последовательно запрашивает описание, необязательный дедлайн
и необязательный номер катера. Кнопки позволяют открыть списки активных и выполненных задач,
выбрать задачу, задать плановый срок в формате `ДД.ММ.ГГГГ`, взять её в работу, выполнить,
добавить комментарий или вложение и открыть карточку на сайте.

## Workflow табеля

```text
Работник: Черновик → На утверждении → Утверждён
              ↑             |
              └─────────────┴─ Отклонён с комментарием

Мастер / «только время»: заполнение → Сохранено (без согласования)
```

Утверждать табель работника могут мастер его участка, начальник производства и администратор.
Вторая ступень согласования не используется.

Основные правила:
- время обеда автоматически вычитается из продолжительности смены;
- при отправке сумма трудозатрат должна равняться отработанному времени;
- в черновике неполное распределение часов разрешено;
- окончание смены раньше начала не допускается;
- для работ по катеру обязательны его номер и описание;
- дробные часы можно вводить с точкой или запятой; 5 минут = 0,08 ч;
- переходы по статусам и редактирование после отправки попадают в аудит.

## Интерфейс

- Адаптивная вёрстка на **Bootstrap 5** для компьютеров, планшетов и смартфонов.
- Мобильные карточки записей затрат вместо широкой таблицы.
- Фирменный логотип River Brothers, плавные анимации и поддержка системного уменьшения движения.
- Отдельные рабочие страницы для каждой роли.
- Дашборды и графики на **Chart.js**.
- Подсветка ошибок, предупреждений и статусов согласования.
- Печатная форма табеля без элементов управления.
- Русскоязычный интерфейс и локализованные сообщения валидации.

## Установка и запуск

### Через Docker

```bash
git clone https://github.com/twixkox/WorkTimeTracker.git
cd WorkTimeTracker
cp .env.example .env
```

Заполните локальный файл `.env`: обязательно задайте `ADMIN_PASSWORD`, а для Telegram — параметры
из таблицы ниже. Файл `.env` добавлен в `.gitignore`; токен нельзя сохранять в `appsettings*.json`,
README или других файлах репозитория.

| Переменная `.env` | Параметр приложения | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | `Telegram:BotToken` | Токен, выданный BotFather. Пустое значение отключает polling и отправку в Telegram; сайт и внутренние уведомления продолжают работать |
| `TELEGRAM_ENGINEERING_CHAT_ID` | `Telegram:EngineeringChatId` | Числовой ID инженерного чата, в котором разрешено создание задач |
| `TELEGRAM_SITE_BASE_URL` | `Telegram:SiteBaseUrl` | Базовый адрес сайта для кнопки «Открыть на сайте», например `https://worktime.example.com` |

`TELEGRAM_SITE_BASE_URL=http://localhost:8080` подходит только для проверки на том же компьютере.
Для сотрудников укажите доступный им внешний адрес сайта без завершающего `/`. При использовании
другого публичного имени также добавьте его в `ALLOWED_HOSTS`.

#### Создание и настройка бота

1. В Telegram откройте проверенного [@BotFather](https://t.me/BotFather), выполните `/newbot`
   и следуйте инструкциям. Скопируйте выданный токен в `TELEGRAM_BOT_TOKEN` в `.env`.
   Не отправляйте токен в чаты и не публикуйте его; при утечке отзовите его через BotFather.
2. Создайте отдельный инженерный чат и добавьте в него бота. Разрешите боту читать и отправлять
   сообщения. Для пошагового создания задач и добавления комментариев в группе отключите режим
   приватности бота: в BotFather выполните `/setprivacy`, выберите бота и установите **Disable**.
   Если Telegram запросит повторное добавление бота, удалите его из группы и добавьте снова.
3. Перед запуском приложения отправьте любое сообщение в инженерном чате и откройте
   `https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates`, подставив токен.
   В ответе найдите `message.chat.id` нужного чата и запишите его в
   `TELEGRAM_ENGINEERING_CHAT_ID`. У групп и супергрупп ID обычно отрицательный
   (у супергрупп часто начинается с `-100`). Не используйте ID личного аккаунта или `@username` бота.
4. Убедитесь, что указан корректный `TELEGRAM_SITE_BASE_URL`, затем запустите приложение:

```bash
docker compose up --build
```

Сайт будет доступен по адресу `http://localhost:8080`, если не изменены `BIND_ADDRESS` и `APP_PORT`.
После запуска каждый пользователь привязывает свой Telegram одноразовым кодом из профиля.

#### Long polling и сеть

Бот использует **long polling**: приложение само устанавливает исходящие HTTPS-соединения к
`api.telegram.org`. Webhook настраивать не нужно, дополнительные входящие порты, публичный IP
и проброс портов для бота не требуются. Опубликованный порт `APP_PORT` относится только к сайту.
Если ранее для этого бота настраивался webhook, удалите его через метод Bot API `deleteWebhook`.
Для работы polling нужен исходящий доступ контейнера к Telegram. Не запускайте несколько экземпляров
бота с одним токеном: они будут конкурировать за одни и те же обновления.

#### Данные и вложения

Том `appdata` монтируется в `/app/App_Data` и сохраняет базу SQLite, ключи защиты данных и каталог
`engineering-attachments` с файлами задач. Не удаляйте том при обновлении контейнера и включайте
его в резервное копирование. Вложения хранятся под случайными именами, а исходное имя и тип файла —
в базе. Максимальный размер одного вложения — **20 MiB**; комментарии и вложения доступны как на сайте,
так и через Telegram-сценарии первой версии.

### Локально с SQLite

1. Установите [.NET 8 SDK](https://dotnet.microsoft.com/download) или более новый совместимый SDK.
2. Запустите приложение:

```bash
cd src/WorkTimeTracker
dotnet run
```

3. Откройте адрес из вывода команды, по умолчанию `http://localhost:5000`.

Для локального запуска Telegram-настройки можно передать переменными среды
`Telegram__BotToken`, `Telegram__EngineeringChatId` и `Telegram__SiteBaseUrl`.
Пустой `Telegram__BotToken` отключает только Telegram-функции. Не записывайте реальный токен
в файлы `appsettings*.json`.

База SQLite и начальные справочники создаются автоматически. Для использования Microsoft SQL Server
предусмотрены `appsettings.MSSQL.json` и скрипт `db/001_create_and_seed.sql`.
