# WorkTimeTracker — веб-приложение для учёта рабочего времени

Автоматизирует заполнение табелей, контроль трудозатрат, утверждение табелей и отчётность
для подразделений **Сборка**, **Столярка**, **Швейка**, **15**, **Малярка**, **Сварка**,
**Склад** и **Водитель**. Для склада и водителей доступен упрощённый режим: только время смены,
без записей затрат и утверждения.

## Технологический стек

- **C# / ASP.NET Core 8.0** (Razor Pages, серверный рендеринг)
- **Microsoft SQL Server** — основная СУБД; **SQLite** — встроенный режим «запуск из коробки»
- **Entity Framework Core 8** с миграциями
- **ASP.NET Core Identity** — аутентификация и роли
- **Bootstrap 5** — адаптивный дизайн (удобно со смартфона), **Chart.js** — дашборды
- **ClosedXML** — экспорт/импорт Excel
- **xUnit** — модульные тесты (31 тест: валидация, расчёты, workflow, уведомления, биндер decimal)

## Роли

| Роль | Возможности |
|---|---|
| **Employee** (сотрудник) | Заполняет свой табель за день (или неделю для участка «15»): начало/окончание, четыре начальные строки «№ катера / время затрат / выполненные работы», внутрицеховые работы. Сохраняет черновик, отправляет на утверждение, видит статусы и комментарии при отклонении, историю, сумму часов за месяц. |
| **SectionMaster** (мастер участка) | Табели и статусы сотрудников своего участка, проверка (сумма часов, переработка), утверждение/отклонение с комментарием, редактирование с записью в аудит, сводка по катерам и загрузка, экспорт участка в Excel. Видит только свой участок. |
| **ProductionHead** (начальник производства) | Все участки, сводные отчёты (трудозатраты по катерам, распределение по участкам, загрузка), дашборды с графиками, экспорт в Excel, финальное утверждение (опционально, при двухступенчатой схеме). |
| **Admin** | Справочники (подразделения, сотрудники, катера, виды работ), пользователи и роли, привязка сотрудника к учётной записи, сброс паролей, журнал аудита, системные логи с разделением по уровням, настройки, импорт из Excel, любые отчёты. |

## Workflow табеля

```
Черновик → (отправка) → На утверждении → (мастер) → Утверждён
     ↑                        |
     └──── (отклонён с комментарием) ┘
```

Все переходы и редактирование после отправки записываются в журнал аудита (`AuditLogs`). Системные
события и ошибки HTTP-запросов сохраняются в `ApplicationLogs` и доступны администратору на странице
«Журнал логов». Подразделения в режиме «Только время» не используют workflow утверждения.
После окончания смены мастерам отправляется одно сводное уведомление по участку со списком
сотрудников без табеля за день. Уведомления доступны всем ролям на отдельной странице.

## Валидация

- из времени между началом и окончанием смены автоматически вычитается 1 час обеда;
- сумма затрат (по катерам + внутрицеховые) не может превышать отработанное время
  (при отправке — ошибка с подсветкой строк, в черновике — предупреждение);
- окончание раньше начала — ошибка;
- переработка (больше порога, по умолчанию 8 ч) — предупреждение с пометкой;
- для записей без флага «внутрицеховые» обязательны № катера и описание работ;
- для внутрицеховых работ описание необязательно;
- дробные часы принимаются и с точкой, и с запятой («6.5» / «6,5»);
- пороги настраиваются администратором (макс. часов в день, порог переработки, шаблон смены);
- стандартная смена — 09:00–18:00; время можно изменить в каждом табеле и в настройках.

## Запуск (SQLite, без установки СУБД)

```bash
cd src/WorkTimeTracker
dotnet run
```

При первом запуске автоматически создаются: база `worktime.db`, роли, справочники,
учётные записи (таблица ниже). Откройте http://localhost:5000 (или порт из вывода `dotnet run`).

## Запуск на Microsoft SQL Server

1. Скопируйте `appsettings.MSSQL.json` → `appsettings.json` (или задайте переменные окружения
   `ConnectionStrings__Default` и `Database__Provider=SqlServer`).
2. Примените миграции:

   ```bash
   dotnet tool restore
   dotnet ef database update --project src/WorkTimeTracker
   ```

3. Выполните SQL-скрипт начального заполнения: `db/001_create_and_seed.sql`.
4. `dotnet run` — seeder досоздаст роли, администратора и демонстрационный состав участков.

```
└── db/001_create_and_seed.sql   # MSSQL: создание БД и начальное заполнение справочников
```

## Печатная форма

Страница табеля мастера (`/Master/Day`) оптимизирована для печати: кнопка «Печать»
скрывает элементы управления, формат близок к бумажному табелю для подписи.

## Реализованные этапы

- **MVP**: справочники, личный кабинет сотрудника, экран мастера с утверждением,
  простые отчёты, экспорт в Excel, валидация, аудит.
- **Этап 2**: недельный вид (участок «15»), внутрисистемные уведомления, аналитика
  и дашборды начальника производства, адаптивный дизайн.
- **Этап 3**: аудит действий, печатная форма, настройка ролей и параметров через интерфейс,
  импорт данных из Excel.

## Примечания

- Приложение целевой платформы `net8.0`; если установлен только более новый .NET SDK,
  работает за счёт `RollForward=LatestMajor`.
- Регистрация новых учётных записей через страницу регистрации доступна только администратору.
